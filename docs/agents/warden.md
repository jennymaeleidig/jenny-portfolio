# Warden scope

How pi-warden selects the files it audits in this repository, and what each developer must set in their own user config. The config that carries the exclusions is [`.pi/pi-warden.json`](../../.pi/pi-warden.json); the extra extensions live in the user file, because the audit sends every file it discovers and that choice is the developer's.

## Per-developer step

Add the Markdown and CSS source extensions to `~/.pi/agent/pi-warden/config.json`. The project file cannot carry this key.

```json
{
  "rules": {
    "auditExtensions": ["md", "css"]
  }
}
```

Without this, the audit still judges the built-in shell and JavaScript files but skips `content/`, `docs/`, and `assets/site.css`.

## Named only

The walk never sees dot-paths or extensionless names. These stay judgeable by naming them explicitly; everything else in those buckets is config, licence text, or a binary asset.

```sh
/warden rules audit --max 20 \
  Makefile vocabulary/career-sections vocabulary/categories vocabulary/statuses \
  .husky/pre-commit .husky/pre-push .github/workflows/deploy.yml
```

`assets/fonts/LICENSE-FONT` is licence text; `.prettierrc.json`, `.prettierignore`, `.pi-lens.json`, and `.gitignore` are config; `.pi-warden/rules-audit.md` is the generated audit report.

## Verification

```text
/warden rules
/warden status
/warden rules audit . --max 200
```

The audit dialog should name 87 files. A higher count means `md` or `css` is missing from the user file or an exclusion did not load; a lower count means a source extension or skip pattern is wrong. The project config is read only when Pi trusts this project.
