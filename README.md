# jenny-portfolio

Jenny Leidig's portfolio: a static site at `https://portfolio.jenny-page.online`, replacing `jennyleidig.straw.page`.

It is a walking skeleton. One hand-written project is rendered, built and deployed by the machinery every later page will extend.

## Where the decisions are

- **[Wayfinder: jenny-portfolio](https://github.com/jennymaeleidig/jenny-portfolio/issues/1)** is the map: the destination, and one line per decision with a link to the ticket that holds its detail. Seventeen decisions, all closed.
- **[Build the site: static portfolio on a monospace grid](https://github.com/jennymaeleidig/jenny-portfolio/issues/20)** is the spec: what gets built, the seams it is tested at, and what is out of scope.

Read the map to understand *why*, the spec to understand *what*.

## What it will be

- `/` with six featured projects, `/work` as the catalogue, `/projects/<slug>` for a single project.
- `/work/<category>` for each of `games`, `sound`, `hardware`, `web` and `articles`.
- `/resume` as the complete record, with `/resume.pdf` and `/resume.md` exported from it.
- `/about` and `/now`.
- Content is one markdown file per project with YAML frontmatter.
- Generated by [jenny](https://github.com/hmngwy/jenny) from vendored bash, deployed by GitHub Actions to Pages.
- Monospace character grid, warm paper, a slow pixelated sky behind it.

### The catalogue

`/work` lists every project in one table, three columns: category and year,
title, blurb. The default order is newest year first. A project with an
`order` in its frontmatter is pinned above the rest, lowest number first, so
older work can sit at the top when it should be met first. The slug breaks
ties, so the order is stable between builds.

A project's blurb is the first paragraph after its `# Title`, rendered from
markdown to HTML. That keeps the catalogue copy and the page's opening prose
in one place. Articles are the exception the catalogue carries: each links
straight to its `paper` or `live` URL (preferring `paper` when both exist),
and the build emits no `/projects/<slug>` page for it.

The front page carries one line about what she does, then shows the projects
marked `featured: true` as cards on the character grid, with the same
category, year and blurb.

## How the build works

`make build` produces `dist/`, a deployable tree:

1. `scripts/stage.sh` reads `content/projects/*.md`, validates its frontmatter, strips it, writes a dated CommonMark file and a shell-sourceable metadata sidecar. A missing required field, a `cv: true` entry without a `cv_blurb`, an article without a `paper` or `live` link, a declared cover that does not exist, or a filename outside `^[a-z0-9-]+$` fails the build with the file named. Articles get a sidecar but no staged markdown, because they have no page.
2. `vendor/jenny/bin/jenny` renders each staged file at `/post/<slug>.html` using `layouts/post.sh`.
3. `scripts/post-build.sh` relocates each page to `/projects/<slug>/index.html`, writes `/`, `/work/` and the five `/work/<category>/` pages, copies `/assets`, and discards jenny's unused index and feed.

The build empties `dist/` before generating, sets `cmark-gfm` as the markdown parser, and fails if a project cannot be staged or a page is not emitted.

`vendor/jenny/` is `hmngwy/jenny` v1.2.5, unmodified, with its MIT licence. Its version and upstream commit are in `vendor/jenny/VERSION`.

## Assets

- `assets/reset.css` is the reset from [The Monospace Web](https://github.com/owickstrom/the-monospace-web), carried over verbatim.
- `assets/site.css` is the grid forked once from the same project, with its attribution and MIT notice intact. It is light only, uses the site tokens, and keeps the `round(down, ...)` rules behind `@supports` fallbacks.
- `assets/sky-core.mjs` is the sky's pure core: hash, value noise, fBm, tone bands and the ordered-dither quantiser. It is imported by both the browser layer and the tests.
- `assets/sky.js` is the browser half: it picks a fresh seed per visit, snaps a block to whole device pixels, re-quantises the cached field each frame, and stops on `visibilitychange`, when the canvas leaves the viewport, or under `prefers-reduced-motion`.
- `assets/nav.js` is the progressive navigation enhancement: internal page links swap `<main>` and the title through `history.pushState` instead of reloading. The sky canvas lives outside `<main>`, so it keeps running across page changes. Without it, or when a fetch fails, links behave as ordinary links.
- `assets/sky-poster.svg` is a static frame at the shipped 2px cell size, shown when JavaScript is off or no 2D context can be created. It is generated from the same core by `node scripts/sky-poster.mjs`; the frame is embedded as a base64 PNG so the committed file stays text inside the no-binaries rule. The SVG records a frame hash that the tests check against the core.
- `assets/fonts/CommitMonoV143-VF.woff2` is Commit Mono v1.143, the `wght 200-700`, `ital 0-1` variable font, self-hosted and preloaded. Its SIL Open Font License sits beside it as `LICENSE-FONT`. It is the one binary file committed to the repo.

## Local development

Install the build dependencies:

```sh
# macOS
brew install cmark-gfm gawk gnu-sed grep coreutils

# Debian or Ubuntu
sudo apt-get install cmark-gfm
```

Node is only needed to run the tests.

```sh
make build   # writes dist/, the same tree CI deploys
make test    # builds into a temporary directory and checks the emitted files
make clean
```

## Deployment

A push to `main` runs `.github/workflows/deploy.yml`: build, test, upload the Pages artifact, deploy. The workflow does not commit a `CNAME` file; the custom domain is configured in the repository's Pages settings.

Enabling Pages (source: GitHub Actions) and pointing the domain at it are one-time human steps in repository settings, tracked apart from the build.
